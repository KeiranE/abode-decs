# Email enquiry setup
The form is independent of WhatsApp. In this draft it is not connected and clearly reports that no email is sent. No recipient email has been supplied.
Set assets/config.js enquiryEndpoint to a same-origin server endpoint once hosting is chosen. The frontend submits JSON: name, email, phone, service, area, message, website (honeypot). Successful API response must be {"sent": true} only after the email provider confirms acceptance. This is not an inbox-delivery guarantee.
The server must validate types, lengths, email and allowed services; reject honeypot entries; rate-limit requests; add server-side spam protection; send from a verified sender to the configured private recipient, with the customer's email used as Reply-To. Escape user content in email templates. Keep mail-provider credentials and recipient settings on the server, never in frontend code. Use a provider appropriate to the final hosting platform. Test valid submission, invalid payload, spam/rate limit, provider failure and recipient delivery before launch. Record provider/retention in the privacy notice. No backend or email provider has been provisioned in this static draft.

The guided journey submits the existing name/email/phone/area/service/message/website fields, plus structured project data. Server-side validation must allow and validate property, occupancy, service-specific details and rooms. The email must include the full enquiry summary. Contact and project text length limits must accommodate the questionnaire.
